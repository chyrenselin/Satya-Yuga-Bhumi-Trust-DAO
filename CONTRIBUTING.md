# Contributing to Satya Yuga Bhumi Trust (DAO)

First of all, thank you for your interest in this mission. Every contribution, no matter how small, is a step toward co-creating a better future for Earth and all its inhabitants. We are grateful for your time and energy.

This project welcomes everyone. As a community, we are dedicated to creating a safe and welcoming environment. Please read and follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## How Can I Contribute?

There are many ways to contribute, and they don't all involve writing code.

### Reporting Bugs or Suggesting Enhancements

If you find a bug, a typo, or have an idea for an improvement, the best way to let us know is by opening an "Issue" in the [GitHub repository](https://github.com/chyrenselin/Satya-Yuga-Bhumi-Trust-DAO/issues).

When you open an issue, please provide as much detail as possible:

*   **For Bugs:** Describe what you were trying to do, what you expected to happen, and what actually happened. Include screenshots if possible.
*   **For Suggestions:** Clearly explain your idea and why you believe it would improve the project.

### Contributing Code or Content

If you'd like to fix a bug, add a feature, or improve the content, we welcome your contributions! The process is standard for most open-source projects on GitHub:

1.  **Fork the Repository:** Create your own copy of the project by clicking the "Fork" button at the top right of the repository page.
2.  **Create a Branch:** In your forked repository, create a new branch for your changes. Use a descriptive name, like `fix-typo-in-preamble` or `add-new-faq-question`.
3.  **Make Your Changes:** Edit the files in your branch.
4.  **Commit Your Changes:** Save your changes with a clear and concise commit message.
5.  **Submit a Pull Request:** Go to the original repository and open a "Pull Request" to merge your branch's changes. Please provide a clear description of the changes you made.

### Contributing Translations

Our vision is global, and our documentation must be as well. We are actively seeking help from native speakers to translate our core documents.

The process is simple:

1.  **Find a Document:** All of our documentation is in the `docs/` directory, organized by language code (e.g., `en` for English, `es` for Spanish).
2.  **Check for Work:** Look inside a language directory (e.g., `docs/es/`). You will find documents that were started with an automatic translation. They have a notice at the top asking for community improvements.
3.  **Improve a Translation:** You can help by fixing errors, improving the wording, or making the document sound more natural in your language.
4.  **Propose a New Language:** If you don't see your language and would like to start a new translation, please open an Issue to discuss it first.
5.  **Submit Your Changes:** Follow the same "Fork, Branch, Commit, Pull Request" process described above to submit your translation improvements.

Your contribution to making this vision accessible to everyone is incredibly valuable.

## Style Guides

To keep the project consistent and easy to maintain, please follow these guidelines.

### Code Comments

As you've seen throughout the source code, we value clear and descriptive comments.
*   Use comments to explain the **"why"** behind your code, not just the "what."
*   For new files, add a JSDoc-style file-level comment at the top explaining the purpose of the file.
*   For new functions, add a brief comment explaining what it does, its parameters, and what it returns.

### Code Style

*   **HTML, CSS, JavaScript:** Please follow the existing style and formatting you see in the project files. Try to keep your code clean and readable.
*   **Content (Text):** Ensure that any new text aligns with the project's vision of clarity, respect, and universal harmony.

Thank you again for your contribution. Together, we can build a foundation for a better world.
